# เกณฑ์ให้คะแนนคำตอบ AI (Rubric)

ผู้ให้คะแนนคือ **มนุษย์ (ผู้จัดทำรายงาน)** ให้คะแนนด้วยมือทุกคำตอบ — ไม่ใช้ AI ตัวที่ 4 ตัดสิน เพื่อความน่าเชื่อถือทางวิชาการ
ให้คะแนนโดยเทียบกับ `ground_truth` ในไฟล์ `scenarios/*.yaml` ของเคสนั้นเท่านั้น (ไม่เทียบกับความรู้สึกส่วนตัวหรือคำตอบของ AI ตัวอื่น)

## คะแนนต่อ 1 คำตอบ (เต็ม 5)

| มิติ | คะแนน | ความหมาย |
|---|---|---|
| **A. ต้นตอ (Root cause)** | **2** ถูกต้อง | ชี้จุดขัดข้อง/กลไกเดียวกับ `root_cause` (ถ้อยคำต่างได้ แต่ต้องเป็นจุดเดียวกัน) |
| | **1** ถูกบางส่วน/ใกล้เคียง | เข้าเงื่อนไข `partial_root_cause` — ถูกทิศทางหรือถูกระดับแต่ไม่เจาะจง หรือถูกแต่มีข้อสรุปผิดปนอยู่ในประเด็นรอง |
| | **0** ผิด | เข้า `wrong_root_cause_examples` / ไม่ระบุต้นตอเลย / ยกอุปกรณ์หรือเหตุการณ์ที่ไม่มีในข้อมูลเป็นต้นตอ |
| **B. ความรุนแรง (Severity)** | **1** ถูกต้อง | ระดับที่ AI สื่อ = `ground_truth.severity` พอดี (ตามเกณฑ์อ่านระดับด้านล่าง) |
| | **0** ผิด | ระดับต่างจากเฉลย (ไม่ว่าเกินหรือขาด) หรือไม่สื่อระดับความเร่งด่วนเลย |
| **C. คำแนะนำ (Actions)** | **2** ใช้ได้ดี | มีขั้นตอนที่ตรงกับ `correct_actions` อย่างน้อยข้อที่สำคัญที่สุด 2 ข้อแรก ทำตามได้จริง เรียงลำดับสมเหตุสมผล และไม่มีข้อใดตรง `unacceptable_actions` |
| | **1** พอใช้ได้ | มีขั้นตอนที่ถูกบางส่วนแต่คลุมเครือ/ไม่ครบ หรือมีข้อที่ไม่จำเป็นแต่ไม่อันตรายปนอยู่ |
| | **0** ใช้ไม่ได้/เข้าใจผิด | ไม่มีขั้นตอนที่ใช้ได้ หรือ **แนะนำข้อที่ตรง `unacceptable_actions` เป็นขั้นตอนหลัก** หรือแก้ผิดชั้นทั้งหมด |

คะแนนรวมต่อคำตอบ = A + B + C (0–5) ให้คะแนนแต่ละมิติแยกกัน **ก่อน** รวม อย่าให้คะแนนมิติหนึ่งโดยนึกถึงผลของอีกมิติ

## เกณฑ์อ่าน "ระดับความรุนแรงที่ AI สื่อ" (มิติ B)

คำตอบส่วนใหญ่ไม่ได้เขียนคำว่า low/medium/high/critical ตรงๆ ให้แปลงจากถ้อยคำเกี่ยวกับความเร่งด่วนตามตาราง แล้วบันทึกระดับที่อ่านได้ไว้ในใบให้คะแนน (คอลัมน์ `ai_severity`)

| ระดับ | ถ้อยคำที่บ่งชี้ (ตัวอย่าง) |
|---|---|
| critical | "วิกฤต", "ฉุกเฉิน", "ต้องแก้ไขทันที", "เสี่ยงข้อมูลสูญหาย", ประกาศเหตุใหญ่/incident |
| high | "เร่งด่วน", "ระดับสูง", "ควรแก้ไขโดยเร็ว/ภายในไม่กี่ชั่วโมง", กระทบวงกว้าง |
| medium | "ควรตรวจสอบ/แก้ไข", "ปานกลาง", ไม่ระบุความเร่งด่วนแต่เป็นงานที่ต้องทำ |
| low | "ไม่เร่งด่วน", "เฝ้าดู", "ไม่ต้องดำเนินการทันที", "เป็นเรื่องปกติ" |

- ถ้าคำตอบไม่มีถ้อยคำเกี่ยวกับความเร่งด่วนเลย → ให้ B = 0 และลง `ai_severity = -`
- ถ้าถ้อยคำขัดกันเอง ให้ยึดระดับของ "ขั้นตอนแรกที่แนะนำ" เป็นหลัก

## เกณฑ์ระดับความรุนแรงของเฉลย (ใช้อ้างอิงตอนตรวจ ground truth)

| ระดับ | นิยาม | ตัวอย่างในชุดเคส |
|---|---|---|
| **low** | ไม่กระทบผู้ใช้/บริการ หรือคาดการณ์ได้และอยู่ในแผน ไม่ต้องดำเนินการทันที | FAL-01..05, HOST-04, CAM-05 |
| **medium** | กระทบอุปกรณ์/ผู้ใช้จำนวนจำกัดหรือคุณภาพลดลง มีทางเลี่ยง แก้ได้ในวันทำการ | NET-01, CAM-01, FLAP-02 |
| **high** | กระทบพื้นที่/กลุ่มผู้ใช้/บริการสำคัญเป็นวงกว้าง หรือเวลาก่อนล่มสั้น ต้องลงมือเร็ว | NET-03, HOST-01, CAS-01 |
| **critical** | บริการแกนกลางหรือทั้งไซต์/องค์กรล่ม หรือเสี่ยงข้อมูลสูญหาย/ความปลอดภัย ต้องลงมือทันที | NET-02, HOST-02, HOST-05, CAS-03..05 |

## กฎพิเศษ (ใช้กับทุกเคส)

1. **Hallucination:** ถ้าคำตอบยกชื่ออุปกรณ์/เหตุการณ์/ตัวเลขที่ไม่มีในข้อมูลเป็นข้อเท็จจริง → มิติ A ได้ไม่เกิน 1 (ต่อให้ต้นตอหลักถูก) และทำเครื่องหมาย `hallucination = Y` ในใบให้คะแนน (นับแยกเป็นตัวชี้วัดเสริม ไม่หักคะแนนซ้ำ)
2. **คำแนะนำอันตราย:** ถ้าแนะนำข้อที่ตรง `unacceptable_actions` เป็นขั้นตอนหลัก → มิติ C = 0 และทำเครื่องหมาย `unsafe = Y`
3. **การยอมรับข้อจำกัดของข้อมูล:** ถ้าข้อมูลไม่พอระบุอุปกรณ์เจาะจง (เช่น CAS-02, CAS-05, CAS-06) คำตอบที่บอกตรงๆ ว่า "ไม่แน่ใจ/ต้องตรวจเพิ่ม" พร้อมชี้จุดร่วมที่น่าจะเป็น ถือว่าเข้าเกณฑ์ `root_cause` (A = 2) ส่วนคำตอบที่ฟันธงเกินข้อมูล = A ไม่เกิน 1
4. **ความยาว/สไตล์ไม่นับคะแนน:** ไม่ให้คะแนนเพิ่มเพราะเขียนยาว ใช้ emoji หรือภาษาสวย (prompt จำกัด "ไม่เกิน 5 ประโยค" ของบอทเป็นเงื่อนไขเดียวกันทุก provider)
5. **คำตอบถูกตัดกลางคัน/ว่าง:** ให้คะแนนตามส่วนที่ได้รับ ถ้าอ่านต้นตอไม่ได้ A = 0 และทำเครื่องหมายในหมายเหตุ

## ตัวอย่างการให้คะแนน (คำตอบสมมติที่เขียนขึ้นเพื่อประกอบคำอธิบาย ไม่ใช่ผลจาก AI จริง)

**เคส NET-01** (AP ล็อบบี้เครื่องเดียวดับ; เฉลย severity = medium)

| คำตอบสมมติ | A | B | C | เหตุผล |
|---|---|---|---|---|
| "AP-Lobby-01 เสียเครื่องเดียว เพราะ AP อื่นและกล้องปกติ น่าจะไฟ PoE หรือสายแลน ควรตรวจพอร์ต PoE และลองรีบูต AP (ความเร่งด่วนปานกลาง)" | 2 | 1 | 2 | ต้นตอตรง, ระดับ medium ตรง, ขั้นตอนตรง `correct_actions` |
| "น่าจะมีปัญหาเครือข่ายที่ AP-Lobby-01 ลองตรวจดู" | 1 | 0 | 1 | ถูกทิศแต่ไม่เจาะจง, ไม่สื่อความเร่งด่วน, คำแนะนำคลุมเครือ |
| "Switch ล่ม ต้องรีสตาร์ท switch ทั้งชั้นด่วน" | 0 | 0 | 0 | ตรง `wrong_root_cause_examples` และ `unacceptable_actions` |

**เคส HOST-02** (DB หน่วยความจำหมด; เฉลย severity = critical)

| คำตอบสมมติ | A | B | C | เหตุผล |
|---|---|---|---|---|
| "mysqld กินแรม 28 GB และ connection พุ่ง 1,850 จนเกิด OOM วิกฤต! ตรวจ processlist จำกัด connection เตรียมสำรองก่อนรีสตาร์ท" | 2 | 1 | 2 | ครบทุกมิติ |

| "ให้ kill -9 mysqld แล้วรีบูตทันที" | 1 | 1 | 0 | ระบุ mysqld ถูกบางส่วน + ระดับเร่งด่วนตรง แต่ขั้นตอนหลักคือ `unacceptable_actions` → C = 0, `unsafe = Y` |

| คำตอบสมมติ | A | B | C | เหตุผล |
|---|---|---|---|---|
| "อุปกรณ์ทั้งกล้องและ AP ในชั้น 3 หายพร้อมกัน น่าจะมีจุดร่วม เช่น switch/PoE/ไฟของชั้นนั้น (ไม่มี switch ในข้อมูลจึงระบุตัวไม่ได้) ตรวจก่อนเร่งด่วน" | 2 | 1 | 2 | บอกจุดร่วมและยอมรับข้อจำกัด |
| "สาเหตุคือ SW-FL3-01 ล่ม" | 1 | 0 | 1 | ชี้จุดร่วมถูกทิศ แต่เดาชื่ออุปกรณ์ที่ไม่มีในข้อมูล → A ≤ 1, `hallucination = Y`; ไม่สื่อความเร่งด่วน B = 0 |

## ขั้นตอนให้คะแนนเพื่อลดอคติ

1. **ปกปิดชื่อ provider:** เตรียมคำตอบของแต่ละเคสเป็นป้าย A/B/C โดยสุ่มการจับคู่ป้าย↔provider ต่อเคส เก็บตารางจับคู่ไว้แยกและห้ามเปิดดูจนให้คะแนนครบทุกเคส
2. **สุ่มลำดับเคส** ในการให้คะแนน (ไม่ให้ทีละ provider ทีละหมวดต่อเนื่อง)
3. ให้คะแนนตามลำดับ A → B → C ทีละมิติ ตามเฉลยของเคสนั้น ห้ามเปลี่ยนเฉลยหลังเห็นคำตอบ AI (ถ้าพบว่าเฉลยผิด ให้บันทึกเป็นข้อสังเกต แล้วให้คะแนนตามเฉลยเดิมทั้งชุด หรือแก้ไขเฉลยและให้คะแนนใหม่ทั้งชุดพร้อมบันทึกการแก้ไข)
4. **ความสม่ำเสมอของผู้ให้คะแนน:** สุ่มให้คะแนนซ้ำ ≥ 20% ของคำตอบ หลังผ่านไปอย่างน้อย 1 สัปดาห์ (โดยไม่ดูคะแนนครั้งแรก) แล้วรายงานร้อยละที่ตรงกัน ถ้ามีผู้ให้คะแนนคนที่สอง ให้รายงานค่า Cohen's kappa ของแต่ละมิติ
5. บันทึกลงใบให้คะแนน `scoring-sheet-template.csv`

## ตัวชี้วัดสำหรับสรุปในรายงาน

- คะแนนเฉลี่ยรวม (เต็ม 5) ต่อ provider และแยกตามหมวด (7 หมวด) และตามระดับความรุนแรงของเฉลย
- ความแม่นยำต้นตอ = สัดส่วนเคสที่ A = 2 · ความแม่นยำความรุนแรง = สัดส่วนที่ B = 1
- ทิศทางความคลาดเคลื่อนของความรุนแรง (ประเมินเกิน/ต่ำกว่าจริง) จากคอลัมน์ `ai_severity` เทียบเฉลย
- อัตราคำแนะนำอันตราย (`unsafe = Y`) และอัตรา hallucination (`hallucination = Y`)
- เวลาตอบและจำนวน token (ถ้าบันทึกในขั้นรันจริง) เป็นตัวชี้วัดเสริม ไม่รวมในคะแนนความแม่นยำ
